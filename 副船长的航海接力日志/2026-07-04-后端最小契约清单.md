# 2026-07-04 后端最小契约清单

## 判断

甲方前端形态可能从微信小程序变成 H5。后端不应该跟着摇摆。

最稳策略：

```text
后端先搭业务骨架。
小程序/H5 只接同一套接口。
```

## 后端六根主梁

### 1. 用户身份

责任：

- 游客可浏览公开内容。
- 进入详情、选民登记、参与竞选、提交材料前必须完成身份。
- 身份由手机号 + 微信 openid/wxid + 归属地组成。
- 归属地首次选择后需要二次确认。

最小接口：

```text
POST /mini/login
POST /mini/bind-location
GET  /mini/me
```

### 2. 归属地

责任：

- 提供 122 个归属地。
- 支持镇街、行政村/社区筛选。
- 不做复杂隔离，只做分级默认过滤。

已有接口：

```text
GET /village-v2/list
GET /village-v2/all
```

### 3. 换届母档案

责任：

- 一场换届活动是业务主轴。
- 挂归属地、选举方式、日期、审批状态、阶段状态。

已有接口：

```text
GET  /election-v2/list
GET  /election-v2/detail
POST /election-v2/add
POST /election-v2/update
```

### 4. 岗位

责任：

- 一期只做主任、副主任、委员。
- 自动生成岗位，挂到 election_id。
- 参与竞选必须绑定具体岗位。

已有/新增接口：

```text
GET  /position-v2/list
GET  /position-v2/detail
POST /position-v2/generate
POST /position-v2/add
POST /position-v2/update
POST /position-v2/delete
```

已完成：

```text
POST /position-v2/generate
```

### 5. 母公告 + 子公告

责任：

- 母公告是活动动态看板。
- 子公告按时间线阶段挂在母公告下面。
- `我是选民` 属于母公告活动确认。
- `参与竞选` 不在母公告泛按钮里，必须在具体岗位旁边。

已有接口：

```text
GET  /notice-v2/list
GET  /notice-v2/detail
POST /notice-v2/add
POST /notice-v2/update
POST /notice-v2/delete
```

需要补强：

```text
parent_notice_id 或 parent_id
stage_key
template_code
```

### 6. 材料 / 候选人 / 通知

责任：

- 前台自荐从具体岗位进入。
- 用户提交材料。
- 后台审核材料。
- 材料通过后进入候选人链路。
- 材料驳回后通知用户。
- 后台导入候选人不能删。

已有接口：

```text
POST /material-v2/submit
POST /material-v2/review
GET  /material-v2/list

GET  /candidate-v2/list
POST /candidate-v2/import
POST /candidate-v2/review
POST /candidate-v2/result

GET  /notification-v2/list
POST /notification-v2/send
POST /notification-v2/delete
```
