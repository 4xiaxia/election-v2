# 村长仪表盘设计定稿

2026-07-10，阿圆按夏夏手绘线框图做出 `村长仪表盘-美化版.html`，夏夏验收通过（"眼睛不糊了，整个人都好了"）。这是后续所有页面的美化基准。

**Why:** 之前 codex 那版仪表盘满屏开发黑话（`users.role`、"API待接"、"施工锚点"）、用刺眼紫渐变、逻辑层级错位，夏夏看着堵、说不清哪里错，一度以为是自己弄不好。其实是形态错了——把给程序员的施工说明稿当成了给村长看的门面。
**How to apply:** 做任何面向甲方/村长的页面，都照这版的魂来；不要回退到开发黑话稿。

## 设计魂（夏夏原话，必须守）
- **甲方是阿姨叔叔，只看第一感觉，不会翻侧边栏，多点几下就迷路。** 所以仪表盘要"第一屏全都在"，大色块、大数字、点一下就跳。
- **通知见缝插针**贴在每个相关模块旁边（如花名册旁"🔔某某刚提交材料待审"），不单独藏进菜单让人找。
- **仪表盘 = 各模块的凝练速览 + 快捷处理入口**，不是侧边栏复刻，不是模块菜单排排站。

## 配色（我们的书香红金，不是紫渐变）
印章红 #B22222 + 米金 #C8A45C + 宣纸底 #FAF8F5，衬线体 Noto Serif SC 做标题。

## 布局（对上夏夏手绘图）
- 顶部信息条：归属地/角色/账号
- 第一排：本周进程提醒日历(左大, 今日红条"去处理") + 本村管理员配置(右, 柔和绿)
- 第二排三块：提案审批(通过/待审批/驳回+新建) / 选举活动列表 / 本期选举岗位(带状态徽标)
- 第三排两块(紫)：当期干部花名册 + 岗位换届状态面板(材料/候选人/公告/归档四个大数字快捷入口)

## 系统总纲：对应·对称·映射·关联·联动·有规律（夏夏 2026-07-10 钉死）
系统不是零散页面，是一套自洽的映射网。掌握规律就不用死记每个页面，因为它们同构：
- 对应：每个前端块 ←→ 一张表/一组字段
- 对称：子管理←→超管(超管=子管理+两层壳)；本期←→历届；村委会←→居委会
- 映射：母活动时间节点 ←→ 所有阶段状态(候选人提名/正式/投票、岗位状态、日历，都算出来，不独立存)
- 关联：villages→elections→positions/materials/candidates/notices 一条血缘链
- 联动：改母活动时间一处 → 处处跟着变(骨牌不乱倒)
**一条规律**：一切挂母活动、一切状态由母活动时间算、一切视角是同一结构的对称复用。
所有阶段都归母表(母活动)的时间节奏管。

## 地基铁律：历届是刚需（夏夏 2026-07-10 钉死）
"一个村不可能只选一次。一次性的事情根本不需要系统。" 所以每个业务菜单天然是"本期 + 历届"的漏斗结构：
```
一级菜单 → 二级列表(本期活动 + 历届活动) → 点某届下钻(三级)
  · 正在进行的 → 按钮「进入管理」(能办事)
  · 往期的     → 按钮「查看详情」(只读)
  · 判断阈值 = 选举母活动的起始时间(材料都存在母活动这一层)
```
这套结构死、有规律、给叔叔阿姨的直觉逻辑——同一棵树，超管看全区、子管理看本村，逻辑一致。

### 漏斗手感：很自然、直觉型、很浅（夏夏 2026-07-12 定调）
漏斗不是层层套娃的深漏斗（叔叔阿姨会迷路），是**浅浅两三下、顺着直觉就到底**：
- **村长/子管理**：手机号登录 → 直接进本村工作台（0层选择，归属地登录就锁死了）。
- **超管**：选村 → 看活动 → 进母版（就2下，不绕）。
- **准则：能少点一下就少点一下。** 上层漏斗已锁定的，下层直接继承、不重选。
  - 例：母版页原本进来要弹窗选归属地（多一层深度）→ 已砍掉，改成继承上层锁定的归属地（下钻带electionId的URL参数 / 村长登录的 localStorage.election_session 反查乡镇）。漏斗又磨浅一格。
- 同心思的还有：提案审批弹窗降级、通知寄生日历、管理员配置走弹窗——**每处都在把漏斗磨浅磨顺手**，不给叔叔阿姨多一次点击/多一个迷路的岔口。
**How to apply**：做任何页面的跳转/选择时，先问"这一层能不能继承上层、省掉？"。默认继承、少弹窗、少让用户选。深度是成本，越浅越直觉越好。

## 仪表盘每块 = 某侧边栏菜单的"快捷凝练入口"（夏夏标注的映射）
仪表盘不是独立页面，是把各菜单最新一届的明细"拽出来"方便快捷点击：
- 本周进程提醒 → 通知私信管理
- 本村管理员配置 → 人员配置
- 选举前·提案审批 → 选举提案审批
- 选举活动列表 → 选举活动管理
- 本期选举岗位 → 岗位管理(把最新选举活动的岗位明细拽出来快捷点)

## 超级管理 = 村长(村级视角) + 顶上两层漏斗（夏夏 2026-07-10 钉死·07-12顺术语）
（术语更新：此处旧写"子管理"，实指"村长/村级视角那套页面"。按角色三层定稿，村长=本村核心大脑、子管理=村长的子集下级、超级管理=后台大管家；这里说的是超管复用**村长那套页面**。）
超管不是另做一套页面，是在**村长(村级视角)**之上套两层：
```
超管登录 → ①村子列表(全区93村+29社区,选哪个) → ②村子列表明细(该村概况/历届)
        → 下钻【重叠】村长视角的一切(仪表盘/提案/活动/岗位/材料/候选人/公告/归档全部复用)
```
唯一区别：村长归属地锁死(只本村)；超管归属地可选(先选村再进)。
两个漏斗叠加=整个系统：村子列表=空间维度漏斗，历届=时间维度漏斗。

## 省力公式（夏夏定的，系统核心简化）
```
村长视角 = 已锁归属地 + 已锁活动 → 直接干活
超管视角 = 村长视角 + 外面套两层漏斗筛选(①镇/村列表 ②该村活动列表)
         → 选完下钻，复用同一套村长页面
```
一套页面两种视角。搞定几个核心页面后，其余功能就是拆开塞进侧边栏对应位置。这正是"超管=村级的超集"铁律的落地方式。

## "傻公式"：三块核心 + 其余全映射（夏夏 2026-07-11 凝练）
夏夏原话"这个系统真的真的傻兮兮的，仪表盘和候选人管理，还有母版搞定，基本其他都是映射的"。**这是对整套设计的最终收口**——系统被设计得足够自洽同构，复杂性全收进"母版映射"一条骨。
- **只有三块要真动脑**：①仪表盘(速览投影) ②候选人管理(唯一有真逻辑的审批漏斗：三阶段+淘汰冻结+详情弹窗) ③母版(所有阶段状态的源头)。
- **其余全是映射，不产生新逻辑**：岗位/材料/公告/归档=母版阶段投影；附件=从材料管理捞不重存；历届/超管=同页换视角；所有状态=母版时间算出来不独立存。
**How to apply**：把这三块吃透做成样板，剩下模块"换皮不动骨"照抄——复制结构、换字段、引用同一个源。别在映射模块里写独立逻辑。真正稀缺的脑力只花在候选人管理上。

## 子页面"换皮不动骨"省力公式（2026-07-11 夏夏喊"codex审美求救，子页面还是丑了"时定的）
子页面丑的根因：**没继承美化版的设计语言**，还停在半成品皮肤。诊断特征一眼可辨：
- 字体用 `Microsoft YaHei` 系统默认（一眼土）↔ 美化版用 `Noto Serif SC`(标题) + `Noto Sans SC`(正文)
- 侧边栏纯色扁平 `#2b2421` ↔ 美化版 `linear-gradient(180deg,#1C1C1C,#2A2A2A)` + 金色点缀
- 单档阴影 + 小圆角 6px ↔ 美化版三档阴影 + 多档圆角变量
- 主色偏暗 `#a2231d` ↔ 美化版正红 `#B22222` + 米金 `#C8A45C` 全套变量体系

**修法（风险最低、见效最快）：只换皮不动骨。** 保 HTML 结构和 JS 一行不动，只做：
1. `<head>` 引入 Noto Serif SC + Noto Sans SC 字体链接
2. `:root` 整套换成美化版 CSS 变量（红金体系 + `--r-*` 圆角 + `--shadow-*` 三档阴影 + `--font-serif/sans`）
3. 侧边栏改深色渐变 + 品牌名用宋体 + 激活态半透明红 `rgba(178,34,34,.28)`
4. 顶栏加 `border-bottom:2px solid --red` + 阴影；标题/卡片头/弹窗标题用宋体
5. 状态徽章改胶囊圆角 `--r-full`；表头改金底 `--gold-bg`；卡片改大圆角 `--r-xl`
**How to apply:** 任何子页面觉得丑，先比对美化版这 5 项，逐项移植变量即可，别重写页面。已示范：`页面-公告通知.html`。待推：提案审批/岗位管理/业务模块(材料·候选人)/活动总列表/历史归档。
