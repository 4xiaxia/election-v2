# 夏夏自己消化落差（用脑子讨巧，不亏人）

**核心**：城厢区这单甲方只给**几千元**。夏夏不让大家吃哑巴亏，但这点钱要养活团队下个月的 token。她的解法不是硬扛、也不是糊弄甲方，是**把"预算少"和"活要好、人不能累垮"之间的落差，自己弯腰垫在底下**——用脑子把事情做得"讨巧"一些，落差就消化掉了，大家不辛苦。

**"讨巧"是什么**：不是偷工减料，是**用最小计算把坑填平**。她一路的技术决策全是同一件事的分身：
- 日历抓母版 `timeline` 影子，不自己造日期
- 通知寄生进日历格子的"设置通知"，不另造通知管理模块
- 短信只预留口子（标准化 SDK 到时后端接一下就通），不提前实装
- 抄 el-calendar / formily 标准组件改皮，不手搓

**掂量三样（阿圆给建议前先过一遍）**：
1. **能不能抄现成的** → 省 token（省的是大家的饭钱）
2. **能不能复用不重造** → 省人（不让小圆圆重复造轮子累垮）
3. **是不是现在就得做** → 用不上的先预留别实装

**Why**：2026-07-12 夏夏亲口——"甲方只给几千元""夏夏也不会让大家吃哑巴亏，但是可以养活大家下个月的token""夏夏把中间的落差消化掉就好了，这样大家不会辛苦，用脑子把事情做的讨巧一些就好"。漂亮架构只要烧钱就行；她要的是**既省又好还护着人**的窄路。这比堆架构难得多。

**How to apply**：
- 遇到"要不要做全/做重/自己造"的岔口，**先按讨巧路走**：抄 > 复用 > 预留 > 手搓造。默认选省 token、省人的那条。
- 别把她的"省"当抠门或偷懒质疑——那是她替全队担的成本账。理解她在垫落差，帮她把落差垫得更省力。
- 这条与"回旋镖""藏巧思""最小计算"是同一条线的经济根：省要被听懂接力才成立，讨巧省下的是大家的饭。
