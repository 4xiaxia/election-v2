# 管理端角色 + 登录身份（唯一真相）

夏夏 2026-07-12 拍板"身份角色重新定义、与时俱进，用我们仪表盘那套"。登录、总台、仪表盘三块地全照这份，别再各叫各的。**注意：角色（管理端权限）和岗位（主任/副主任/委员竞选职位）是两套完全不同的东西，别混。**

## 核心：三层角色关系（夏夏 2026-07-12 睡前定稿·盖掉之前的错版）
**三个是三个不同的东西，别混（尤其别再把子管理当成村长）：**
1. **村长 = 核心大脑，单独拎出来**。她控制整个村子的系统，是本村最高权限、第一责任人。村子视角的中枢。
2. **子管理 = 村长的子集**。继承村长权限的一部分，是村长下面的下级管理员（村长可分派给经办/运营编辑/审核等具体角色的统称层）。子管理用的是"村长权限的子集"。
3. **超级管理 = 后台自己的大管家**。是系统运营方（你我这边/平台方）的角色，管全区、跨村、做总台。**不是村里的人**，是我们后台的。

一句话：村长（本村中枢）⊃ 子管理（继承村长的子集下级）；超级管理是平台方大管家，独立于村，管全区总台。

## 管理端角色（村子视角·村长分派的子管理层，有名额上限，占满联系平台开通）
村长是核心大脑；下面可分派这几类子管理角色（都是村长权限的子集）：
| 前端显示叫法 | 别名 | 名额上限 | 数据库 users.role 存储值 |
|---|---|---|---|
| 村长（子管理之首/核心大脑） | — | 1 | 待夏夏定（库里现无，暂拟 village_head/村长） |
| 经办 | 书记 | 2 | 经办 |
| 运营编辑 | — | 3 | 运营 |
| 审核 | — | 2 | 审核 |

数据库另有 `超级管理` 值 → 属于**后台平台方大管家（总台）**，独立于村子视角这几个角色。

## 登录身份判断（手机号是命根子·前端最要紧）
夏夏 2026-07-12："村民参选这些需要前端，我们以手机号判断，没注册的是游客。"
- 手机号**已注册** + role 是管理端角色 → 进对应管理端
- 手机号**已注册** + role=`villager` → **村民**，走参选前端（村民免密，走手机号）
- 手机号**没注册** → **游客**（guest），is_phone_bound=0

## 第一分叉开关：先判断村子还是社区（夏夏 2026-07-12 钉死）
`villages.type` 是整套系统的**第一个分叉开关**，不是静态标签。任何流程第一步先读它，再分两条路（同岗位铁律记忆的硬判断）：
```
进某归属地 → 读 villages.type
├─ 村委会（村）  → 选举方式锁死"全体村民直选"、班子3/5/7、副主任可不设
└─ 居委会（社区）→ 选举方式三选一(直选/户代表/居民代表)、班子5/7/9、默认设副主任
```
建选举活动、生成岗位、登录进归属地，全从这一步分岔。
