# 候选人审批三阶段漏斗表

夏夏 2026-07-11 定稿。**开放问题已闭环：候选人审批合并进"候选人管理"模块，不另开独立审批模块。** 理由：审核本就分3阶段、且3阶段状态由母版时间算（不独立存），再拆独立审批=给同一份数据开两个门，违反"一份数据一个源"。

## 查看详情弹窗（夏夏 2026-07-11 补）
点"查看详情"走**弹窗**（不跳页），只读展示用户提交的自荐表原文 + 附件：
- **基础字段模板（初步候选人自荐表）**：自荐人姓名 · 自荐职务 · 性别 · 出生年月 · 民族 · 文化程度 · 是否党/团员
- **附件预览**：甲方要求用户提交**复印件**，所以必须能**预览**附件（图片直接展示、PDF内嵌，其他格式兜底下载），不是只挂文件名/下载链接——审批人要边看复印件边在三阶段表里✓✕。

## 表结构
- **面包屑**：首页工作台 / 候选人管理 / 历届候选人名录 / 第N届候选人审批 [返回列表]
- **母版状态同步条**：顶部显示当前母版阶段（如 🔴提名候选人）+ 起止日期（如 2026-07-16 至 2026-07-25）
- **候选人池双来源**：
  - 来源1：材料审核通过 → 流入池
  - 来源2：后台导入（党组织/线下联名直接导入池）——有 [+后台导入名单] / [表单导入] 按钮
- **表列**：# | 姓名 | 竞选岗位 | 推荐形式 | 查看详情(弹窗) | 当前状态 | 审批操作（三阶段横排）
- **三阶段横排**，每格 ✓ / ✕ / 理由：
  1. 提名候选人
  2. 正式候选（入围）
  3. 最终竞选

## 两条核心规则（骨）
1. **操作列随母版阶段动态变**：母版推进到"正式候选人公示"阶段时，操作列自动变为 [确认入围正式] / [取消资格]。按钮文案跟着母版阶段走，不写死。
2. **淘汰冻结（选举漏斗的锁）**：上一阶段被 ✕ 掉的人，**下一阶段那一格的 ✓✕ 勾选口不再显示、冻结起来**。一层层筛，被淘汰者后续阶段的门自动锁死。淘汰=状态终止，后续阶段对他关闭。这与"状态由母版时间算、不独立存"同构。

## 落码默认（阿圆先定，夏夏未拍则按此，做出来给她审）
- 被冻结的格子显示灰标"已止步·未通过提名"之类，而非留空（免得表看着像漏数据）。

**How to apply**：做候选人管理页时，审批就是这张三阶段漏斗表，不做独立审批模块。勾选口的显隐由上一阶段结果决定，操作按钮文案由母版当前阶段决定。
