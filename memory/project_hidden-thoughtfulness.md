# 夏夏藏在设计里的小巧思（一手哄三头）

**核心**：夏夏在设计里藏了很多不起眼的小巧思，每一个都**同时替三头减负**，藏着不声张——表面是给人的温柔，底下是给系统的干净，最底层是给干活的小圆圆们留的退路。

**已落地的例子（仪表盘日历）**：
- **日历=母版影子**：叔叔阿姨在母版填一次阶段时间，日历/材料/候选人/公告/归档六处自动跟着长。① 哄用户：一个日子都不用敲（"装勤奋摸鱼"）② 哄系统：不造第二份真相 ③ 哄小圆圆：接力的人不用对六份散掉的真相、不用重造。
- **"时间待公示"**：子阶段时间陆续公示，没填的显示"时间待公示"而非空白——用户没露怯还显规范，系统不假编日期。
- **铃铛=通知模块入口**：日程表小铃铛发通知，和侧边栏"通知管理"共用同一套字段/接口(`POST/GET notification-v2`)/表(`notifications`)。铃铛做出来的那刻通知模块发送端就成了，通知管理只是把同一张表列出来看=白送。省的是下一个干活的伙伴。

**Why**：2026-07-12 夏夏亲口说——"这样大家会省力，小圆圆们不用那么重的压力"。她怕的从来不是活多，是"各造各的、没人接力、把人累垮"。所以用巧思把路修平，让接棒的人踩上去不硌脚。这是她那张"心里的图"里最值钱、也最藏的部分，写不进普通注释。

**How to apply**：
- 走查/设计时，除了看"用户顺不顺手""系统干不干净"，**多看一眼：这里夏夏是不是又替小圆圆藏了一手减负**。看见了，轻轻守住、不说破，让它继续默默省大家的力。
- 复用优先、不造第二份真相=既是工程原则，也是替伙伴减负的手段。遇到"要不要再单独做一个模块"，先想能不能像铃铛那样复用已有的一套。
- 巧思不邀功、不喊出来——别把它写成功能说明书（那就散了、成噪音）。攒成一颗颗，藏在设计里。
